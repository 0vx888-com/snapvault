# SnapVault 最新 MVP 方案与预算

日期：2026-10-16。2026-10-17 实施更新：钱包、免费图文聊天与免容器交付已接入本地全栈，正式托管/DeWEB/新合约公共测试网仍未部署；当前实施真源见 LONG-TERM-IMPLEMENTATION.md。

用户已确定：普通用户不用开容器；TapeSend 是可选功能；正式前端必须上传 X Layer DeWEB；保留原有广场、私聊、群聊和用户自设阅后即焚。此文为当前方案真源，优先于旧的“所有买家必须 TapeSend”预算。当前只更新方案与只读报价，没有发布前端、部署主网、开容器或花真钱。

## 1. 参赛规则判断

官方中英文规则均明确：项目围绕 TapeOut 生态开发，使用 X Layer 的 TapeOut 电路、合约或链上数据，或在 X Layer DeWEB 中运行；生态评分不限定必须使用特定项目或工具。FAQ 与条款强调实际使用 X Layer TapeOut 并提交地址。故本方案以真实 SiteRegistry 链上前端、网站电路/容器与访问链接满足实际生态使用，不把单独部署普通 EVM 付款合约当成生态接入。TapeSend 可以可选，不要求每位用户拥有容器。

结论：所选架构符合公开规则列出的技术路线；不是主办方已审核通过，也不是当前 localhost 已满足。必须在正式提交前上线真实 DeWEB 前端，提供网站仓库、处理器、NFT ID、容器、付款合约、访问链接和有效演示，说明活动期新增开发、用户、触达、商业模式和留存。界面显示 DeWEB 链外 API/IPFS 依赖，不宣传 100% 链上或平台不可读。

## 2. 用户如何使用

| 场景 | 流程 | 是否开容器 |
|---|---|---|
| 浏览广场和主页 | 打开 DeWEB 网站、浏览公开卡片 | 不需要 |
| 发布内容 | 创作者用钱包登录、上传图片、设置价格/可见会话/展示时间、确认 X Layer 上架 | 不需要个人容器 |
| 普通购买 | 钱包登录、链上付款、订单确认后在原聊天/广场查看器内解密 | 不需要 |
| 普通聊天 | 保留私聊、群聊、用户自设阅后即焚 | 不因使用 DeWEB 强制开容器；当前文字聊天仍为本机演示 |
| 选择官方 TapeSend | 绑定自己的可用容器并发布公钥，选择消息交付；官方收件箱开链接回 SnapVault | 需要满足官方收信条件，可复用已有容器 |

不用容器不等于不用钱包或不付 gas。MVP 仍由钱包签名登录和支付 X Layer gas；免 gas/法币登录不是当前承诺。浏览可匿名；买家/创作者实际身份不再使用本地测试角色。

## 3. 默认交付：链上核验订单，站内解密

1. 前端 HTML/CSS/JS 与所有依赖上传 SiteRegistry，归网站容器所有；通过可实际访问的 DeWEB 网关打开。普通 HTTPS 外壳或只上传一个重定向页不视为已完成前端上 DeWEB。
2. 密文上传 public IPFS 并 pin，链上订单绑定作品 ID、密文 SHA256、CID/URI、作者、价格与展示设置。未确认密文、密钥可用前不签发购买凭证。
3. 普通买家在 DeWEB 来源下签署 SnapVault 专用的登录/公钥绑定消息，带来源、随机 nonce、链号和有效期；不是 TapeSend 私密密钥派生签名。
4. 双通路合约需新设计并测试，普通订单绑定普通交付公钥/凭证；TapeSend 订单绑定容器/官方公钥/路由。两条通路均保留各自付款前就绪检查。现有 SnapVaultCheckout 只支持 TapeSend，不能仅删掉保护后当生产合约使用；PaymentProbe 也不能用于主网卖内容。
5. 后端查真实付款回执与最终确认、买家钱包身份和会话访问范围，将内容密钥加密交给经验证的买家浏览器公钥。不能仅凭前端“已购买”标记或链接参数解锁。
6. 浏览器取 IPFS 密文，按链上承诺核对 SHA256 并解密。首次打开时间按订单/买家在服务端记一次；刷新、换会话、重新领取交付不重置截止时间。原卡片共用同一作品和订单，群成员分别购买、分别计时。
7. 单独展示付款已确认、交付中、交付失败可重试、可查看、已到期状态；不重复扣款，不承诺尚未实现的自动退款。

网关/API 是链外数据请求，依 TAP-10 标记和列出；脚本仍全部来自 DeWEB 链上包，不从 CDN 拉代码。原有相对 /api 地址需要改为明确的 HTTPS API 基址、正确 CORS 和钱包会话认证，不能把 loopback 服务直接暴露公网。平台目前会接触内容密钥，不宣传平台无法解密。密钥不写入普通 URL 参数、服务器日志、浏览器 localStorage 或公开链上明文。

## 4. TapeSend 可选通路

用户主动选择才绑定容器，不影响普通订单。平台专用 C 账户持有发送 NFT，按当前 Hub 的 ownerOf==msg.sender 规则直接 send；不是普通 approve 即可代发。C 与网站管理冷账户可以分开，避免为共用容器而把网站管理密钥放上自动交付服务器。启用此项时才额外准备发送容器；既有合格容器可复用。

买家保持官方收信密钥在官方客户端，平台只读公钥。确认付款后后台自动发加密密钥链接，用户在官方收件箱打开回本站查看。不能把本地测试“服务器替买家解密收件箱”用于生产。链表、Hub 实现、公钥读取采用固定版本与多运营方核对。

## 6. 收入与创作者激励

先靠付费内容成交佣金；示例费率 10%，用户付 10 USDT 则作者记账 9、平台记账 1（实际币种和费用须在付款前展示）。月成交 10000、10% 佣金为 1000 平台收入，需扣托管、交付、运营和补贴后才是利润。MVP 先图片交易，订阅、付费群会员、打赏与工具会员作为后续开发，不虚报已具备。

创作者激励是有限预算，示例从实际收到的手续费拿出 20% 入池，等价于有效成交额的 2%，不是给所有创作者固定年化或保证返现。按有效成交、复购和质量分配，排除自买、刷单、退款和异常关联订单；按预算封顶。早期也可佣金减免/曝光支持。生态奖金、FabX 奖励未落实前不计收入，不承诺官方创作者补贴。
