## 自动服务如何接入

`config/live.example.json` 是公开配置模板；真实配置放 `config/live.json`（Git 已忽略）。`RELAYER_KEYSTORE` 和 `RELAYER_PASSWORD` 由钱包所有者仅在本机设置，用于解锁专用测试服务钱包。不要发送给开发者聊天，不要把它们写进公开配置或 Git。当前没有生成、读取或保存用户钱包凭据。

`server/start.mjs` 仅监听 127.0.0.1，限制 Host/Origin，不能直接部署到公网。`.snapvault-local/` 保存密钥、密文与订单工作状态，默认目录 0700/文件 0600，Git 已忽略。**这是单实例本机测试服务，密钥仍为平台保管，不是生产密钥保险库。** 正式托管需数据库、备份、隔离密钥管理、限流、HTTPS 和部署审查。

处理顺序：签名上传 → 服务检查密文和目标买家 → 买家拥有已开通容器与可用公钥 → 钉住 Hub 实现 → 检查发送方持有权和 gas → 签发 120 秒购买凭证 → 钱包付款 → 等待确认 → 封装 TAP-10 → 本机服务钱包自动发消息 → 买家在官方收件箱开链接 → 服务原子记录首次打开 → 取密文、哈希核验、AES-GCM 解密。

- 用户不会在 SnapVault 签署官方 TapeSend 密钥派生文字，也不会把 TapeSend 私密签名交给 SnapVault。
- 签名凭证绑定当前合约、链、作品 ID、买家、容器和公钥；普通 `purchase` 被禁止，私有作品只向允许的买家签发凭证。
- 并发请求串行化，原始已签名交付交易在广播前持久化；重试同一交易，结合 Sent 事件避免同一订单重复投递。仅适用于当前单实例服务。
- 密钥/持有人变化、内容损坏、Hub 实现变化或 gas 不足会阻止新购买凭证。付款后发生故障仍需人工处理，**没有自动退款保证**。
- 首次打开截止时间存服务端，刷新/重复打开不重置。交付链接是一种持有者凭证，转发链接会转发查看能力；已保存密钥和图片不能收回。
- 当前网关是本机 HTTP 密文接口，不是已验证的公共 IPFS 网关；不同电脑不能使用这个 localhost 链接。公开部署前需改成可达的 HTTPS 服务和真实持久存储。

## 公共测试网完整验收还缺什么

需要 TapeOut 官方提供：1952 上的工厂、处理器、容器开通器、Hub 及实现地址和费用；SDK/收信链表对 1952 的支持；可用的容器开通/公钥发布入口。拿到后需要更新固定配置、核对字节码与权限，再解除 1952 收款保护。另一条是经过用户另行批准预算的主网小额验证，不能以测试币替代。

验收必须同时有部署、上架、付款、Sent 交易回执，以及官方接收客户端解密并从目标网关还原原图的证据。缺少任何一项都不能写“官方测试网端到端已跑通”。
