# 免费网关与手机连接诊断

本轮没有上传、部署、签名、付款、开容器、购买或发送 TapeSend。SPENDING-PAUSED.json 保留，原冻结版本与 38 笔账本不变。

## 已证实

- 链上 21 文件已通过两个独立 RPC 完整字节与 SHA-256 核验。
- 原域名对正式后端 config 与匿名 state 的请求均为 200，精确 CORS 来源正确；healthz 为 200。
- 用户确认手机使用原域名，并能直接看到 healthz 的 status ok / chainId 196。因此不能将手机当前提示直接归因于 Railway 不可达。
- 公开网关仍有独立节点法定数量不足的问题；dRPC 曾多次 HTTP 408。最新轻量请求、批量和 CORS 预检均可成功，不能把它夸大为始终无法连接。
- 官方兼容入口读取同一容器，同一冻结版本 21 文件字节与哈希全部一致，5 次原始 HTTP 首页读取均成功；但独立浏览器冷加载仍出现法定节点不足，且正式后端未允许兼容来源（403）。这不是已完成的稳定入口，不能擅自推荐为修好或改用。

## 已本地修复

冻结源码的 initWallet 在旧会话失效时，收到 401 后清掉旧 token，却中断初始化；app.js 又把该错误显示成通用“暂时连不上服务器”。隔离测试已复现。现在仅在 401 且 token 已清除时重试一次公开 state，恢复未登录页面；500、断网等仍失败，不删除持久设备密钥，不请求签名或交易。

16 项单元/手机适配/交易保护检查及 7 项浏览器就绪检查已通过。完整隔离回归 11 套全部通过，包括 70 项合约/服务/发布检查、16 项单元检查、7 项就绪页面检查、23 项钱包社交页面检查及两轮市场流程。本地源码修改不改变冻结发布目录，也未上链。

用户已明确反馈：原网址显式刷新一次后，错误消失，显示“连接钱包／X Layer 主网”。这是用户报告的手机恢复结果；本轮未重新签名登录或验收聊天。旧会话误报已独立复现，手机没有原始错误日志，因此将其记录为与恢复一致的候选原因，不冒充已经取得手机 401 证据。本地代码修复没有上传，不能说成线上已自动部署修复。

## 稳定访问的实施边界

原公共网关和域名不属于项目，无法通过修改本项目来直接替换它的 Service Worker / RPC 重试策略。免费可控方案应是只读的 DeWEB 缓存网关：先按已批准发布 manifest 的完整哈希核验链上字节，保存最后成功版本，节点短暂超时时继续交付已验证版本，后台低并发重试；新版本未完整通过时不替换旧版本。这样无需再次写链或改合约，但对外长期运行需要一个用户可控制的托管入口。

现阶段不创建托管资源、不切换入口、不扩大后端来源白名单、不购买 RPC，也不把临时隧道说成永久稳定服务。官方兼容入口仍须先完成浏览器与后端联调后才可考虑使用。任何后续发布费用另行说明并等明确授权。
