# 钱包最终最高费用核对（当前只读）

当前禁止部署、上传、钱包签名或任何链上写入。SPENDING-PAUSED.json 不删除，旧授权已消耗，剩余预算不构成新授权。

## 已修复与测试

- 两个单文件上传服务已在启动时直接终止；不再读取旧 approvalGranted 后启动服务。
- 共用上传页已移除 eth_sendTransaction 与连续自动发送。即使 continuous=1 也不能请求钱包。回执与读链核验保留。
- final-wallet-fee.mjs 是纯本地计算器，不连接钱包、不广播、不产生支付许可。type2 使用 gasLimit × maxFeePerGas；legacy 使用 gasLimit × gasPrice。加上转入金额、已花金额后检查总上限。
- 缺最终字段、缺截图/核对记录、身份改变、核对超过60秒均拒绝。两次真实超预算参数均作为回归样例被拦截。
- 16 项本地测试通过；本次未跑整个产品 test:all，未改业务页面或后端逻辑。新费用测试已加入 test:all。

## 后续有新授权时的必要流程

1. 先冻结文件和差量计划，只读核对链上旧哈希、nonce、尚未确认的交易，避免重复。
2. RPC 估算仅为报价，不能称为钱包最终最高费用。先报包含 value 和 gas 的总预算，等用户明确授权。
3. 任何将来新发布工具必须默认禁止自动下一笔。用户在钱包交易详情展开最终 Gas Limit、Max Fee、Priority Fee（legacy 为 Gas Price），先不要确认；由执行者读取并留存截图/字段。
4. 离线核对最终网络196、账户、合约、calldata、nonce、value、费用参数；预算内才能明确通知用户确认这一笔。超限必须取消该草稿，不广播。修改任何参数或换草稿，原核对立即失效。
5. 标准 eth_sendTransaction 没有“暂停在草稿并取得钱包改写后参数”的通用接口。返回哈希时已经广播，不能用回执检查冒充签名前控制。当前旧上传工具永久停用，不声称有可自动保证最终上限的新钱包通路。
6. 后续重新启用发布需另行实现可检查的草稿流程，先在纯本地假钱包验证，再获得当次授权。当前不为验证流程创建主网草稿或请求签名。

本次修复保证旧通路无法继续意外发交易，并正确识别最终费用；不承诺能阻止用户在钱包自行修改后直接确认。不要再次让用户一边连续确认、一边事后审计。
