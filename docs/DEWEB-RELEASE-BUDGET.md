# DeWEB 与正式 TapeSend 发布预算

核验：2026-10-18；X Layer 主网 196；只读，不签名、不广播、不付款。本文替代旧的双容器 HTTPS 方案预算。原始读数见 `deployment/deweb-tapesend-mainnet-budget.json`；可运行 `node scripts/estimate-mainnet-budget.mjs` 刷新。每次发布前重算，不能将这次报价视为固定价格。

## 需要准备多少 OKB

**建议总预留 0.30 OKB，尚未批准花费。** 它覆盖网站、独立发送 C、一个演示收件买家这三个全新容器，以及本轮发布/部署/小额验收的 gas 余量；不是一次性付款，更不是每来一个普通用户都要开容器。普通无容器用户保持普通交付并显示提示。

| 项目 | 规划 OKB | 证据与限制 |
| --- | ---: | --- |
| 三个容器开通 | 0.240000 | 两家独立 RPC 同块读取，每个 FEE()=0.08 |
| 三次电路流片 | 0.003900 | 抽查 CPU4/CPU6 的 TAPEOUT_FEE()=0.0013 |
| 三个最小电路晶体管铸造 | 0.003960–0.004980 | 假设每电路一个 NAND、分别 mint；每单位协议费0.00066，加 CPU4 单价0.00066 或 CPU6 单价0.001；尚未选定处理器或支付 |
| 当前前端上传与 fallback | 约0.00554127 | 15文件、1,172,180字节、60数据块；另有fallback，必要时再做名称激活。逐块 synthetic putFile 模型，不是实际 appendChunk 账单 |
| 新 SnapVaultDirect 部署 | 约0.00005473 | 当前加固字节码 unsigned estimateGas：2,736,412 gas；模拟部署者/treasury不是最终用户地址 |
| 一次实际格式 TAP-10 查看链接 | 约0.00000354 | 假密钥与示意链接，封包487字节、176,666 gas；无真实用户密钥或交易 |
| 其他 gas 与波动余量 | 从0.30预留内支付，逐笔核对 | mint/开通/流片/公钥/名称激活/上架/购买/提现/向C转gas；部分已模拟，最终交易仍须估算，不能当成已得到完整精确报价 |

协议费小计：CPU4假设为0.24786，CPU6假设为0.24888。加前端、业务合约与一次发送，已量化部分约 **0.25346–0.25448 OKB**。尚未精确报价的 gas 和波动由余量覆盖；若实际预估不能落在已批准上限内，必须停止并重新报价。CPU0的免费晶体管已经售罄，不能按零价销售承诺。CPU4/CPU6是价格样本，不是安全背书；创建前核验工厂归属、实现、铸造限制、最小电路有效性和可用库存。无需自建处理器，故不计自建处理器部署费。

最新成功模拟还有：单个开通169,729gas；CPU4一枚NAND mint 92,951gas；公钥发布83,433gas；名称绑定187,404gas。都仅为公共历史持有人身份下的无签名模拟，既不代表我们已有容器，也不是授权使用别人的资产。gasPrice=20,000,001wei。示例未签名 TapeSend 交易在 GasPriceOracle 报数据费0，不推导其他真实签名交易的数据费必定0。

资金安排原则：用户钱包承担网站和合约部署；C仅在需要时转入开容器所需款，完成后只留少量gas，**不把0.30全部放C**；operator只签就绪报价，不需要持有容器或常规发送gas。买家收到的是本轮演示收件容器，日后是否补贴新用户应另作商业决策。内容购买本金是买家到创作者的转账，不计作基础设施消耗，但买家钱包仍需要余额。

## 后续费用

- 短消息500–1000字节当前约0.00000354–0.00000379 OKB/条；1000条约0.00354–0.00379 OKB，另留波动余量。这是链接消息，不把图片塞入TapeSend。
- 绑定 monthlyFee() 当前为0，不承诺永久不收费。网页更新仍要付变更文件的写入gas，一般无需重新买容器。
- Railway、异地加密备份和图片存储/流量是另计的法币资源费用。Railway官方当前有试用额度和免费档，Hobby为每月最低5美元（含相应使用额度，超额另计）；实际档位/额度要在账户确认。独立备份存储账户尚未准备，不把它写成永久免费或已验收。未开通任何新付费套餐。
- 不含兑换/提币/桥接费用、自有域名购买和后续运营规模扩张。使用公共 DeWEB 网关不等于付费独立域名。

## 实际发布顺序

1. 已完成新1952合约双钱包购买、看图、阅后到期和提现；证据为 `xlayerTestnet-direct-v2-acceptance.json`。本地官方Hub交付测试与主网真实发送证据分开保存。
2. 用户确认预算，并提供自己主网owner/treasury公开地址；不得沿用旧测试A。没有这一步不充值、不创建主网容器、不代签金融交易。
3. 按最终身份重新估算网站容器创建和实际交易。分步创建网站容器、上传 **仅dist/wallet**。核验15个文件的链上原字节与SHA-256、fallback和名称激活。当前已有钱包签名发布器，未发布、未得到网站容器ID或最终网址。
4. 正式网关采用 `https://<ID>-2-<CPU编号>.tapekit.org/` 对应X Layer名称；网站字节由DeWEB读链，不用普通托管重定向冒充。2026-10-18已只读取得公共网关引导页和支持196的内核配置；这不等于SnapVault已经在该网关验收。需在真实站点测试钱包注入、手机访问、路径回退、跨域、缓存更新和链接fragment。
5. 发布前处理前端残留“本地链测试/未使用真钱”文案，再固定最终构建并刷新预算。不得在生产主网上架成功后显示测试提示；这项目前仍待修改。DeWEB默认拦截链外请求，需将后端列为明确链外依赖并核验站点状态页的放行体验；构建manifest并不能代替真实浏览器权限验收。
6. 用户钱包部署主网SnapVaultDirect，owner/treasury属于用户；operator用新专用地址。之后后端切196，不关闭链号/地址/实现校验。Railway当前仍为旧测试网服务，不能当新版已上线。
7. 单独准备C和演示买家容器、买家在官方TapeSend发布公钥并启用X Layer收信。C独立于operator。生产WalletService已有TapeSend代码，仍须配置真实容器ID、验证异地加密备份与恢复后才能启用。
8. 用极小金额真实买一次：有可用容器/公钥→purchaseDelivered→C自动TAP-10发送→官方收件箱打开查看链接→浏览器解密；密钥仅放URL的#片段。保存付款、Sent、收件箱及提现证据。无容器回退普通交付且明确提示；已具备容器但C未就绪时不得先收款再静默回退。

**下一次用户动作是预算确认与提供主网公开地址，不需要现在盲签，也不需要发送私钥。** 每个主网交易展示用途、金额、网络和预估gas后再请用户确认。网站发布器有预算/单价门禁，但0.30是本轮总体规划，不是代码已覆盖全部步骤的全局花费锁。
