# SnapVault 三项保护：本地实施与验收（2026-11-05）

本次只修改本地源码、运行合成夹具/模拟 S3/本地浏览器、只读链上文件与费用模拟。不访问生产卷或真实 S3，不删除现有数据或备份，不 push、不部署、不上传 DeWEB、不签署或广播主网交易。

## 实施内容

### 1. 旧消息迁移
- 迁移尊重旧 opens 的原始截止时间。旧过期 DM 不提取成新可读文件；有效未读 DM 保留正文。
- 群聊按接收者迁移，已过期成员不能重开；其他未读成员仍可读，共享正文不会提前删除。
- 旧付费观看记录、已有一次性凭证和销毁标记导入独立日志，迁移重跑不会延长截止时间。
- 作者预览不会误删尚未出售的私聊付费文件。

### 2. 备份恢复与防回退
- 独立 views.journal 使用 HMAC 链与 fsync，记录授予、消费、完成、销毁和业务状态水位；原始访问 token 不写入日志。
- 主网日志钥匙必须与 MASTER_KEY、BACKUP_KEY 不同，持久目录必须显式配置。独立日志不包含在可回退数据库快照中。
- S3 独立命名空间 `snapvault/<chain:contract>/view-ledger-v1/` 保存加密的不可覆盖事件和 CAS 条件更新的 head。内容交付前后需同步验证；较旧/分叉的本地日志、缺失远端 head 但仍有历史对象、无法完成条件写入时，拒绝继续交付。此命名空间不使用快照的清理路径。
- v2 加密备份包含有效未读 burn 文件和日志水位。恢复需可信的当前日志，并重放快照以后的消费/销毁事件；未读正文缺失或损坏则拒绝假成功。
- 如果旧快照遗漏了之后新增的用户、消息、作品或交付业务状态，恢复会拒绝，而不是静默丢失这些写入。不能从过旧备份凭空恢复未备份的新数据；必须继续维护并找到正确检查点/完整状态。
- 只恢复到全新目录，拒绝覆盖原 state 或日志目录；旧快照、源文件不被修改。
- 日志卷丢失时可从可信的当前 S3 水位恢复到新目录，完整校验链与密钥；恢复过程中 head 改变则停止。若本地和远端日志都丢失，保持维护，不重建空记录来开放旧内容。
- 新增暂停本地/S3快照自动修剪开关。主网启动默认暂停修剪；历史备份不因此自动删除。未读正文虽然可恢复，但旧历史副本仍要在另行批准后清理，不能宣称所有备份中的图片已消失。

### 3. 前后端切换和回滚
- `SNAPVAULT_MAINTENANCE=true` 在读取运行配置、加载签名钱包、状态迁移和启动 worker 前接管；健康检查返回 maintenance / ready=false，业务返回503。
- API 版本为 `view-ledger-v2`。主网旧客户端敏感请求返回426，固定 blob URL 仍410；新前端拒绝旧/不匹配后端，并在交易前再次检查版本、链和固定收款合约。
- 只允许一个写进程持有 runtime.lock；异常残留锁不自动删除，需要先证实无写进程再维护处理。
- 主网发送 worker 默认不启用；未授权开启交付 worker 时，付款报价也不开放。维护/恢复验收不会顺便产生 TapeSend 交易。
- 安全回滚预检拒绝旧 manifest 或缺保护的构建。不能把旧不安全镜像回到公网；失败时优先回到此安全构建的维护模式，保留当前 state、burn 文件和独立日志。
- Railway 界面上的手工“退回旧部署”可能绕过本地预检，因此操作规程仍禁止选择 a6f378f 等旧不安全镜像恢复流量。本文没有在真实 Railway 执行回滚。

## 后续发布操作顺序（本轮不执行）

1. 先选择本次安全构建并以维护模式启动。核对所有旧页面、直连API均停写、无发送 worker；保留同一卷和原主网合约。
2. 复制受保护 B0，存入独立 checkpoints 前缀/目录；不能调用会修剪旧快照的普通备份流程。`backup-state checkpoint` 需要明确的停写确认，目标必须新文件，不修改源文件。
3. 配置一把新的服务端 VIEW_LEDGER_KEY，保持原 MASTER_KEY/BACKUP_KEY 不变。新钥匙保存在服务端秘密变量中，不能发聊天或入Git。
4. 首次迁移需显式开关，空日志命名空间初始化也需显式批准。确认 S3 支持条件创建、ETag/CAS 后，在维护状态迁移、建立日志与B1。首次成功后关闭迁移/初始化开关。
5. 从本地B1及S3读回的B1在隔离新目录恢复，验证已看完不复活、未读可读、公开密文/资料/订单仍在。任何校验失败保持维护。
6. 前端只传最终差量；依赖在前、主脚本最后；每笔查回执及哈希，不因RPC超时重复发送。旧缓存版本必须刷新，不提供永久URL兼容后门。
7. 验证正式域名、版本、买家身份、公开字段和旧订单只读查看。不重复主网购买、提现或TapeSend。
8. 通过后解除维护；仅在有明确发送授权和预算时启用交付 worker。历史快照清理始终另给候选清单、另行批准。

## 环境开关（仅说明，未写入任何云环境）

|项|用途|
|---|---|
|SNAPVAULT_MAINTENANCE=true|不初始化业务/钱包，只提供维护响应|
|SNAPVAULT_VIEW_LEDGER_DIR|独立持久目录，恢复时不随旧数据库回退|
|SNAPVAULT_VIEW_LEDGER_KEY|新的32字节hex钥匙，与master/backup不同|
|SNAPVAULT_ALLOW_VIEW_MIGRATION=true|仅首次审阅过的旧数据迁移；成功后关闭|
|SNAPVAULT_ALLOW_LEDGER_INITIALIZE=true|仅确认远端为空后的首次初始化；成功后关闭|
|SNAPVAULT_BACKUP_PRUNING_PAUSED=true|暂停本地/S3旧快照自动删除|
|SNAPVAULT_DELIVERY_WORKER_ENABLED=true|明确启用发送；验收期间保持未设置/false|
|SNAPVAULT_EXPECT_IDENTITY|恢复时明确196及合约身份|
|SNAPVAULT_CURRENT_LEDGER_DIR|恢复时提供当前日志，不是快照中的旧日志|
|SNAPVAULT_EXPECT_LEDGER_HEAD|来自独立当前水位的恢复证明，不能信任旧备份自己声称的head|
|SNAPVAULT_APPROVED_LEGACY_BACKUP_SHA256|仅恢复经审阅旧格式检查点时使用的精确文件摘要|

## 工具

- `scripts/backup-state.mjs verify` 只说明外层加密验证，明确不代表已完成恢复验收。
- `scripts/backup-state.mjs checkpoint`：已停写的离线副本，要求 `SNAPVAULT_OFFLINE_CHECKPOINT_ACK=STOPPED_SERVICE_COPY_ONLY`，不自动修剪。
- `scripts/backup-state.mjs create`：包含未读正文及水位的新格式备份。
- `scripts/recover-view-ledger.mjs inspect`：读独立远端head；`recover NEW_EMPTY_DIR`：恢复日志到新目录。
- `scripts/backup-state.mjs restore BACKUP NEW_PRIVATE_DIR`：校验当前远端水位和本地日志，拒绝覆盖。
- `scripts/check-safe-rollback.mjs ARTIFACT_ROOT`：只读能力预检，不执行部署。

## 验收边界

测试使用合成资料、临时目录和模拟 S3 传输。没有读取生产桶清单、真实账单或生产密钥；S3 服务商实际条件写入兼容性、真实权限和生产备份恢复尚未实测。上线前需获准在隔离前缀验证；不支持CAS时新服务会拒绝交付，不会降级绕过保护。

新日志是追加式记录，不能随意套用“保留12份”清理；将来如需压缩或清理，须另做防回退的检查点设计。本地及云端任何历史备份删除均不属于本轮。

- 浏览器 `burn-chat.spec.mjs`：买家凭证取图、倒计时清图、后端删临时私聊文件通过。
