# SnapVault 长期项目：普通钱包与免容器 MVP

更新：2026-10-17。基于现有前端增量实现，不创建收费资源、不发布主网、不花真钱。

## 现在的入口

- `npm run dev:wallet`：本地完整后台与 Hardhat 31337，打开终端打印的 5185 地址。根页面默认钱包模式。
- `npm run dev`：保留旧本机演示。旧角色、localStorage 购买记录不作为真实后台身份或订单。
- `npm run start:wallet-testnet`：已有公开托管环境后，按 `config/wallet.example.json` 配置 X Layer 测试网 1952。此入口不提供测试角色、自动充值或 RPC 写入代理。

本地启动脚本使用公开 Hardhat 测试助记词，登录的地址得到无价值的本地测试余额。不要向该网络转入真钱。进程重启会创建新的临时链和数据目录；旧目录不会主动删除。这里的本地记录不与公开测试网混用。

## 用户流程

1. 浏览广场不要求钱包或容器。连接兼容 EIP-1193 的钱包后，签署绑定网站来源、nonce、有效期、链号、合约和浏览器 RSA 公钥的专用登录消息。服务验证签名并签发会话；不能通过请求 `who` 冒充别人。
2. 对方先登录，再通过钱包地址加好友，对方接受后创建私聊。选择多位已接受的好友创建群聊，最多 32 人。当前不开放付费群会员或动态移除/新增群成员。
3. 免费发送文字、PNG/JPEG/WebP/GIF 或文字加图片，单图不超过 2 MB；不逐条上链、不逐条付 gas。后台认证会话成员，每个浏览器轮询同步。
4. 普通图文可设置 3–3600 秒的限时展示，界面提供常用时间。每位接收者首次打开时单独保存截止时间；刷新、重新登录、换浏览器不重置。发送者不领取接收者那份限时消息。
5. 创作者在原广场或聊天内上传图片、设置价格、限量、可见会话和展示选项。后台加密并保存密文，浏览器钱包确认测试网上架。聊天内作品只对发布时的成员开放，不进公开广场。
6. 买家获得绑定自己地址与公钥的短期就绪凭证，再在钱包确认 `purchaseDirect`。合约记账、分账、限制重复购买；无需 NFT 或 TapeOut 容器。
7. 服务核验真实链上 `DirectRequested`、确认数、购买期限和会话范围，然后用当前已验证浏览器的 RSA-OAEP 公钥包裹内容密钥。浏览器取密文、校验 SHA256、AES-GCM 解密显示。
8. 付费内容从首次打开开始计时；默认付款后 24 小时内可打开。非限时内容在购买期限内可重复打开。每位群成员独立购买、独立计时。取消付款不创建订单；再次查看不重复收费。

浏览器私有交付密钥保存在 IndexedDB 中的不可导出 CryptoKey；会话令牌保存在 sessionStorage。换设备重新签名登录后，可在原订单剩余期限内领取加密交付，计时不重置。内容密钥不写进 URL、localStorage 或链上明文。

## 后台与边界

- `server/wallet-service.mjs` 提供身份、好友、成员权限、限频、图文持久化、加密资产和免容器交付；原 TapeSend fixture 接口保留在独立旧服务中。
- 数据以 AES-GCM 加密、原子替换文件的方式保存在独立目录，主密钥文件权限 0600。正式托管必须使用持久卷并备份数据与主密钥；会话/登录 nonce 在进程内，重启需重新签名。单进程、早期小规模实现，不支持多副本共享写入；消息/文件有容量限制。
- 平台服务会接触聊天内容与付费内容密钥，不宣传平台无法读取或真实端到端加密。
- 阅后即焚限制后续服务读取与客户端展示，无法阻止截图、改客户端、拍屏或收回已经保存的明文/密钥。
- 免费消息不在链上。付费内容的上架/付款/分账在合约上；价格与买卖地址等链上元数据可见。私有图片的链上元数据也不等于保密。
- 当前图片存储是服务端加密文件与密文下载接口，不是假称已上传 IPFS。后续可接 IPFS pin 或对象存储；IPFS 不是免费聊天或付费解锁的必要条件。DeWEB 前端要求独立保留。
- `SnapVaultDirect` 在原 Checkout 上增加普通交付分支；旧 `purchase` 不能绕过就绪验证。TapeSend 分支保留但不强制普通用户使用；本地免容器 runner 没有部署官方 Hub，不宣称官方 TapeSend 可用。
- 测试服务只允许 31337 或 1952，主网 196 明确禁用。新合约尚未部署公共测试网，旧 PaymentProbe 的部署成功不能当成新合约部署成功。

## 静态前端与 DeWEB

`node scripts/build-app.mjs --api https://实际后端域名` 生成 `dist/wallet/`。所有 JS/CSS/图标/插画和 ethers 依赖随包发布，不从外部 CDN 加载脚本；外部数据 API 在配置与 manifest 中列明。API 使用明确基址，后台配置确切的 DeWEB HTTPS Origin 和 Host，不能使用通配来源。

本地跨来源验收使用：

```
node scripts/build-app.mjs --local --api http://127.0.0.1:5185
python3 -m http.server 5186 --bind 127.0.0.1 --directory dist
```

然后打开 `http://127.0.0.1:5186/wallet-local/index.html`。该路径模拟静态前端与后台分开部署；不是实际 DeWEB 链上上传。`deweb-manifest.json` 记录文件类型、SHA256、大小、24KB 分块规划，`published:false`。

`npm run build:preview` 仅生成另一个明确的本机演示预览包，不能替代有后台的版本。两种包都只允许白名单前端文件，不包含服务器数据、订单、钱包 keystore 或本机测试配置。IPFS 可作为额外静态入口；正式前端仍需上传 X Layer DeWEB。

## 验收与上线顺序

- 合约/服务：`npm test`，含新 `test/Wallet.test.js`。校验凭证绑定、防登录重放、错误来源、真实订单、群权限、持久化和篡改密文时禁止付款。
- 原界面：`npm run test:ui`，指定本机演示 URL。
- 新全栈：`npm run test:wallet-ui`，必须仅连接 loopback 的 Hardhat 环境。使用隔离浏览器与公开测试钱包模拟扩展签名，不操作人的 OKX Wallet。不是已经实测用户 Chrome/OKX 插件的证据。
- 打包验收：`WALLET_UI_URL=http://127.0.0.1:5186/wallet-local/index.html npm run test:wallet-ui`。

公开测试前需要：实际后端托管与 HTTPS、持久化数据卷、服务签名账户的加密 keystore、新 SnapVaultDirect 的 X Layer 测试网地址/部署区块、网站实际 DeWEB Origin。之后由用户在钱包确认测试部署及正式 DeWEB 付费操作，再执行真实插件和跨设备外网验收。

公开测试通过后再开放主网收款。正式长期运营还需补充举报/屏蔽与内容管理、数据恢复演练、服务监控、删除/保留规则和钱包设备兼容性；本次不宣称它们已完成。视频、订阅、激励继续留在后续版本，不阻塞这一轮图片闭环。
