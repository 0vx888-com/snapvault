# SnapVault

在原有黑黄前端上扩展的 Snapchat + 创作者付费内容 MVP，保留私聊、群聊和自己设置阅后即焚。

## 本地体验

```bash
npm ci --ignore-scripts
npm run dev
```

打开 http://127.0.0.1:5173 。无需钱包，所有价格和付款都是本地演示。已有演示数据会保留；不同端口的浏览器数据互相独立。

1. 在「创作者广场」搜索、关注或查看创作者主页；「最新内容」「已购买」展示相应作品。
2. 顶部切换到「小鹿」，在「创作中心」发布图片；也可以在私聊或群聊点「付费图片」，发布后自动回到该会话。
3. 切换到「演示粉丝」，打开同一聊天，模拟购买，再点击查看。购买不立即计时，首次打开才开始；关闭、刷新不会重置。
4. 发布时可关闭阅后即焚，此时购买后 24 小时内可重复查看。开启时可设置 3–3600 秒。
5. 群里的图片每位成员分别购买、各自计时。会话专属作品只向发布时的成员开放；后来入群不自动获得历史专属作品。购买过该创作者作品即可加入示例付费群；阿杰是预设的已购成员。
6. 公开作品可从「创作中心」发送到私聊或群聊，共享同一份购买记录。不同标签页可选择不同演示身份，互相收发消息。

本地图片上限 2 MB，支持 PNG/JPEG/WebP/GIF。该限制来自当前演示存储，不是 TapeSend 的图片上限。普通聊天仍保留自定义阅后即焚与显示保护设置。浏览器无法可靠阻止或检测截图。

## 当前实现边界

| 功能 | 当前状态 |
| --- | --- |
| 广场、创作者主页、关注、搜索、资料编辑 | 本地前端，可操作与保存 |
| 私聊、群聊、好友申请、自定义阅后即焚 | 保留原有模拟传输；跨同源标签页可体验 |
| 付费图片发布、订单、首次打开计时、过期卡片、地址水印 | 前端演示流程已实现 |
| 图片加密与解密、密文 SHA-256 核验 | 实际使用 WebCrypto AES-GCM；密钥与密文仍在同一浏览器本地 |
| 真实收款、提现 | 合约已实现并测试，前端尚未连接合约 |
| IPFS、网关、TapeSend 自动交付 | 尚未实现，当前没有真实上传、消息投递或服务端门控 |
| X Layer / DeWEB 部署 | 尚未进行，提供部署材料和本地演练脚本 |

**本地身份选择和 localStorage 不提供真实身份认证或内容保护。** 当前实现不能用于收费运营，不能承诺端到端私密、链上自动交付、不可保存或彻底删除内容。

## 合约

`contracts/SnapVault.sol` 支持上架/下架、原生币和标准 ERC20 收款、限量、分账、提现。平台费默认 1000 bps（10%），管理员可调整，上限 3000 bps（30%）。不支持转账扣税、rebasing 等特殊代币。

- 每位买家每个作品仅购买一次，过期后也不会重复收费。重新出售需要新作品 ID。
- 购买资格从付款后持续 24 小时；`viewSeconds` 与 `ephemeral` 记录首次打开后的展示选项，由客户端与未来交付服务执行。
- 合约不会自行签名发送 TapeSend，也不能收回已交付的密钥。
- 会话私有范围与成员授权尚未写入合约；当前合约上架和购买都是公开的。接入私聊收费前，需要服务端授权校验与合约购买白名单/买家绑定授权，避免非目标买家付款后拿不到内容。
- 未经审计。所有链上调用、付款和密文 URI 的公开性须在真实接入时明确告知。

## 检查与部署准备

```bash
npm test                      # 9 项本地合约测试
npm run test:model            # 7 项订单/作用域/计时测试
npm run test:ui               # 需先启动前端；使用本机 Chrome，可通过 CHROME 覆盖路径
npm run prepare:deployment   # 编译并导出 ABI、字节码；不发交易
npm run deploy:local         # Hardhat 临时链演练，不是 X Layer 部署
```

UI 回归会使用独立浏览器上下文，不接触个人钱包或现有浏览器数据，截图保存到 `screenshots/mvp-*.png`。合约固定本地 solc 0.8.28，优化 200 次，EVM 目标 paris。前端为原生 JS，不需要构建、不从 CDN 加载依赖。

真实部署步骤、缺少的交付服务与上线顺序见 [部署说明](docs/DEPLOYMENT.md)。`deployment/SnapVault.json` 是公开编译材料，不是已部署合约证明。
